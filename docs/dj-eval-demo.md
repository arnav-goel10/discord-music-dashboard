# AI DJ offline evaluation: harness demonstration

The bot audits every AI DJ recommendation it serves: the ranked slate, the track the listener actually picked, and what happened next (completion, skip, skip severity) are written to `dj_recs_audit_v2`. `scripts/eval_dj_v2.py` turns that audit log into offline metrics, so recommendation changes can be judged before they ship.

This page demonstrates the harness on a **fully synthetic** audit log, so it can run in any checkout with no Discord server, no listening history, and no credentials.

> **Evidence boundary:** every number below is computed from seeded synthetic data generated by `scripts/dev/demo_eval_dj.py` (60-track catalog, 18 artists, 400 recommendation events with position-biased choices and novelty-correlated skips). The numbers characterize the harness and the metric definitions, not the recommender's real-world quality. No real-listener result is claimed anywhere in this repository.

## Reproduce

```bash
PYTHONPATH=. python3 scripts/dev/demo_eval_dj.py
```

The generator is seeded, so the output below reproduces exactly.

## What each metric answers

| Metric | Question it answers |
| --- | --- |
| `hit_rate_at_k` | Was the track the listener picked anywhere in the top-k slate? |
| `mrr_at_k`, `ndcg_at_k` | How high in the slate did the pick sit? |
| `skip_at_1`, `early_skip_rate_at_1` | When the top recommendation played, did the listener skip it, and how quickly? |
| `artist_diversity_at_k`, `artist_repetition_rate_at_k` | Is the slate one artist five times, or an actual mix? |
| `mean_novelty_at_k`, `long_tail_share_at_k` | Is the DJ exploring beyond the obvious hits? |
| `catalog_coverage_at_k` | Over the audit window, how much of the catalog ever gets surfaced? |

The unit tests in `tests/test_eval_dj_v2.py` pin the metric definitions themselves (including track-id reconstruction when the audit row is missing one), and CI runs them on every push.
